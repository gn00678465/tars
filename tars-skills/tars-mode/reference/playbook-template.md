# playbook 範本

寫新的 playbook 時，複製「骨架」一節，填入內容，存成 `playbooks/<名稱>.md`，再在 `SKILL.md` 的路由表加一列。

## 寫之前先分清楚

- 可以用程式檢查的規則、要跨 session 保留的狀態，寫進 `tars` 指令，不寫進 playbook。playbook 的步驟只寫「執行哪個指令、照它的輸出做什麼」。
- 另一個 skill 或 playbook 已經有的規則，寫「照 `<名稱>`」，不重寫一次。
- 一條規則只寫在一個段落。

## 骨架

```markdown
# <名稱>

## 目的

<一到兩句：這個 playbook 做完後，使用者得到什麼。>

## 前提條件

- <什麼請求進入這個 playbook。>
- <什麼請求不進入，改去哪裡。>
- <開始前必須已經有的東西：指令、檔案、另一個 skill。>

## 步驟

1. <一步一個動作。先寫動作，再寫條件。>
2. <要問使用者時，寫明最多問幾題。>
3. <最後一步是交給使用者的東西。>

## 判斷標準

- <步驟裡需要判斷的情況，以及每種情況的做法。>
- <不能做的事，以及原因。>

## 驗證

- <輸入> → <可以觀察到的結果>
- <邊界情況> → <可以觀察到的結果>
```

## 每一段的規則

| 段落 | 規則 |
|---|---|
| 目的 | 寫結果，不寫過程。 |
| 前提條件 | 至少一項寫明不適用的情況。 |
| 步驟 | 用編號。每一步可以獨立判斷做完了沒有。 |
| 判斷標準 | 只放步驟裡用得到的判斷。沒有就刪掉這一段。 |
| 驗證 | 每一項寫成「輸入 → 可以觀察到的結果」。結果要能從回覆、指令輸出或檔案看出來。寫不出可以觀察的結果，表示那條規則沒有辦法確認，改寫或刪掉。 |

輸出格式固定時，在「驗證」之前加一段「輸出格式」。

## 長度

- 一個 playbook 以 100 行為上限。超過時，把只有部分請求用得到的內容移到 `reference/<名稱>.md`，在步驟裡寫「需要 X 時讀 `reference/<名稱>.md`」。
- 範例只放一個。規則說得清楚時不放範例。
