# 用腳本庫取數與開原文

三個 Serenity 劇本的資料步驟都照這一頁。網頁與 `tars claude` 走同一條路：資料只經過入庫的腳本，用 `tars script search` 找。腳本庫是使用者自己的，裡面有哪些腳本因人而異，所以這裡不點名腳本。怎樣算開啟原文、打不開怎麼寫，見 `serenity-method.md`。

## 研究日期

研究日期是今天的台北日期。對話裡看不出今天的日期時（網頁沒有 shell），把它併進劇本步驟 1 的那一題問使用者。後面所有日期都用這一個，寫到跨午夜也不變。來源的 `retrieved_on` 寫研究日期。

## 研究名稱與原文目錄

`--out` 的目錄已經存在時，tars 直接沿用，不會擋，同名的檔案會被覆蓋。所以每次研究在開第一份原文前，先取一個沒有人用過的研究名稱：

1. 研究名稱是 `serenity-<類型>-<對象>-<碼>`：`<類型>` 是 `theme-scan`、`claim-challenge` 或 `arena`；`<對象>` 是代號或題材的英文簡寫；`<碼>` 是你這次隨意挑的 6 個小寫英數字元，不沿用這個對話或範例裡出現過的。全部只用小寫英數與 `-`。名稱不放日期：網頁看不到日期。
2. 確認 `out/<研究名稱>` 不存在：
   - 自建入口（網頁、`tars chat`）：用 `file_read` 讀 `../workspace/out/<研究名稱>`。相對路徑以 skills 目錄為起點，這個寫法會落在 `workspace/out` 底下。回「不存在」才用這個名稱，回覆裡的完整路徑就是原文目錄的絕對路徑；回「不是一般檔案」表示目錄已經在了，換一組碼再查。
   - `tars claude`、`tars agy`：用它們自己的工具看 workspace 底下的 `out/<研究名稱>` 在不在（session 從 workspace 開始）；在就換一組碼。
3. 之後所有 `--out` 都放在 `out/<研究名稱>/` 底下，劇本不另建目錄：腳本的 `--out` 會建它。

限制：查與建不是同一個動作。兩個研究在同一刻挑到同一組碼時仍會共用目錄；6 碼隨機字元讓這件事很少發生，但不是不可能。

## 開啟原文

1. 執行 `tars script search 網頁 markdown --json`，找把網頁或 PDF 轉成 Markdown 的腳本。命中的不合用時，照 `playbooks/script-mode.md` 的步驟 2 用 `tars script list --json` 再找一次。
2. 找到後執行 `tars script show <名稱>`，照它寫的呼叫方式帶參數，並看它的輸出說明：要能回報存檔的路徑。不回報路徑的腳本不拿來開原文，因為不知道該讀哪個檔。
3. 每一份原文執行一次 `tars script run <名稱> --out out/<研究名稱>/<來源 id> -- <網址>`。`<來源 id>` 和報告 `sources` 裡這份來源的相同（`S2`）。`--out` 的相對路徑以 workspace 為起點，所以這樣寫就對。
4. 讀取腳本輸出回報的那個檔，一次讀不完就分段讀到要引用的那一段為止；附註常在後面。自建入口用 `file_read`，路徑用腳本回報的絕對路徑，不寫 `out/…`：`file_read` 把相對路徑接在 skills 目錄後面，會找錯地方。`tars claude`、`tars agy` 用它們自己的讀檔方式。

寫檔的腳本每次執行前都會出一張核准卡，所以一份原文一張。被拒絕時不換方式再試：那一份寫 `not_accessible`，`reason` 寫「擁有者沒有核准抓取」。

找不到能用的抓網頁腳本時，告訴使用者，問一次要不要繼續：繼續就照 `serenity-method.md` 的「原文不足時」交降級的報告；不繼續就結束，說缺哪一種腳本。要寫一支新的腳本時，只能在 `tars claude` 照 `playbooks/script-mode.md` 寫。

找網址：`tars claude` 裡可以用自己的搜尋找網址，但搜尋結果與摘要不算開啟過。網頁沒有搜尋，用已知的網址（公司投資人關係頁面、EDGAR 的公司頁）或請使用者給。

## 市場資料（第一版不依賴）

月營收、單季財報、股價、法人與融資這類數字，先執行 `tars script search 市場資料 股價 --json` 找取市場資料的腳本：

- 有 `approved` 的而且輸出讀得到（stdout，或 `--out out/<研究名稱>/market` 時腳本回報的檔案，讀法同「開啟原文」的步驟 4）：照 `tars script show` 的說明執行。資料來源是 FinMind 時，來源寫 `kind: finmind`（欄位見 `serenity-memo-json.md`）。
- 沒有，或輸出讀不到：數字到財報原文取（月營收與單季財報在公司公告與財報裡）。原文也取不到的寫缺口：`not_accessible`，`reason` 寫「腳本庫沒有讀得到的市場資料腳本」。股價取不到時，估值寫 `unresolved`。

不用其他資料自己湊替代的數字。

## 寫進報告

- 一份腳本輸出對應一個來源。FinMind 的來源寫 `dataset`、`data_id`、`as_of`（輸出裡那個資料集最新一列的日期）與 `retrieved_on`。
- 引用其中的數字時：營收與財報用 `period`（`2026-09`、`2026Q2`），股價、法人與融資用 `as_of`（那一列的日期，不晚於來源的 `as_of`）。
- 營收單位是元，法人是張，股價是元，成交量是股，照實寫。
- FinMind 的最新交易日落後一到幾天（週末與假日後更多），報價的 `as_of` 是資料裡的最新一列，不是今天。
- 美股的財報、營收與籌碼不在 FinMind 的匿名資料裡，到財報原文找，查不到寫缺口。
- 單季財報的數字：EPS 當單季的值引用，不年化、不乘四；估值要近四季合計時，才把連續四個已公布季的單季 EPS 相加。毛利率與營益率只引用單季，不相加。
- 股價是未還原的，跨過除息日算漲跌幅是錯的，不自己還原。

## 腳本的結果

| 結果 | 做法 |
| --- | --- |
| 結束碼 0 | 往下 |
| 核准被拒絕 | 那一份寫缺口，不換方式再試 |
| 結束碼 1 且 stderr 以 `error: ` 開頭 | tars 在腳本開始前就拒絕了，照訊息處理 |
| 其他非 0 | 照 `tars script show` 列的結束碼解讀。網路錯誤稍後重跑一次；再失敗，那一份寫 `not_accessible`，`reason` 寫 stderr 的那一行，不從結束碼猜 |
| 124 | 逾時。原文太大時加 `--timeout`（上限見 `script show`）再跑一次 |
